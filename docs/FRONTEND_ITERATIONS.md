# 前端迭代记录

本文档按轮记录前端分析、改动、实际验证和仍未解决的限制。只有 Codex 明确给出审查结论后，才会记录为已验收；本文件不自行标记验收状态。

约束基线：不操作既有容器/服务，不读取 `.env` 或凭据，不调用外部新闻/AI/通知，不读写用户数据库或共享 `data` 状态；测试只使用临时数据库和 mock。每轮只处理指定范围，不 commit/push。

---

## 第 1 轮：统一视觉基础（Codex 已审查）

Codex 独立验证：页面与阅读回归 7 项通过；新增登录行为测试 1 项通过；改动文件的 Ruff 与格式检查通过。源码审查确认认证、HTML 转义及既有导航保留。浏览器视觉核查留在十轮完成后的统一部署阶段。

### 问题

- 共享视觉只存在于 `dashboard/Home.py` 的几条内联 CSS 中，颜色、字号、卡片和链接样式散落；`news.py` 又单独定义了阅读页样式，页面之间缺少明确的 token 层。
- 原内联样式把全局 `a` 设为青绿色并带 `!important`，选择器过宽，容易波及图表/表格等非导航链接。
- 默认页面顶部留白和一级标题偏大，首页头部显得过高。
- 登录页只有一句 `st.info`，没有说明密钥从哪里来、输入后会发生什么，也没有说明密钥不会被回显或自动填充。

### 改动

- 新增 `dashboard/theme.py`：
  - 集中定义深色背景、面板/表面、分隔线、正文/弱化文字、青绿色强调色、焦点色和字体栈。
  - 提供 `stylesheet()`、`apply_theme()` 与 `card_key()`；样式只使用现有稳定选择器：`.stApp`、`[data-testid="stSidebar"]`、`[data-testid="stMetric"]`、`[data-testid="stMainBlockContainer"]`、`[data-testid="stMarkdown"]`、`[data-testid="stForm"]` 以及按钮容器。
  - 收敛字体层级：压缩 `h1` 尺寸和上边距，统一 `h2/h3`、正文行高、说明文字和 Markdown 链接颜色。
  - 统一指标卡、表单、带 `aih-card-` key 的卡片、按钮、链接、分隔线和可见焦点样式。
  - 窄屏媒体查询只压缩页面/卡片内边距和标题字号，不隐藏任何控件或功能。
- `dashboard/Home.py`：
  - 删除原有内联 CSS，改为在 `set_page_config` 后调用 `theme.apply_theme()`。
  - 登录页改为“眉标 + 标题 + 说明 + 两张卡片”：明确说明从本机 `.env` 输入 `ADMIN_API_KEY`、输入后的行为、窄屏展开侧栏方式，以及密钥不回显/不自动填充/不写入文件的边界。
  - 管理员密钥输入框保持 `type="password"`、默认空值，并显式设置 `autocomplete="off"`；不新增预填值或密钥展示。
  - 概览“最新情报”卡片使用共享 `card_key()` 接入统一卡片样式。
  - 导航 radio 的位置、选项和顺序未改；既有主要按钮标签未改。
- 未改动 `news.py` 的阅读页局部样式；共享主题只提供全局背景、字体、按钮和链接基础，阅读页仍保留自己的标题、摘要、事实框和阅读宽度规则。
- 选择器刻意避开 Plotly、DataFrame 和组件内部 DOM，不覆盖图表配色、表格内部样式或 BaseWeb/React Aria 私有结构。
- 新增 `tests/test_theme.py` 中的一个 AppTest 回归：未登录时不请求 API、密钥输入为空且为密码类型、`autocomplete=off`、登录说明包含进入方式和“已选择的工作空间（默认概览）”、导航顺序不变。

### 实际验证

- 测试命令（运行前显式设置环境变量）：

  ```bash
  DATABASE_URL=sqlite:///:memory: AI_ENABLED=false TELEGRAM_ENABLED=false FEISHU_ENABLED=false \
    env -u PYTHONPATH PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 \
    .venv/bin/pytest -q tests/test_theme.py tests/test_dashboard.py tests/test_news_reading.py \
    tests/test_reader_workspace.py tests/test_visual_reports.py
  ```

  结果：`16 passed, 1 warning in 3.41s`。警告为依赖自带的 Starlette/httpx 弃用提示，与本轮改动无关。覆盖登录/全部工作空间页面、网关错误、运行日志重试、新闻列表与阅读页、简报分页和新增的登录回归。

- Ruff：

  ```bash
  .venv/bin/ruff check .
  .venv/bin/ruff format --check .
  ```

  结果：`All checks passed!`；`78 files already formatted`。

- AppTest 实测：空密钥时只渲染登录页，管理员密钥输入 `label=管理员密钥`、`value=""`、`type=1`（密码）、`autocomplete=off`；导航选项仍为概览/实时新闻/重大事件/行业管理/数据源管理/简报/系统设置/运行日志；登录页不调用 `httpx.request`。
- 未启动 Streamlit/API/容器，未读取 `.env`，未调用任何外部服务或真实模型/通知；测试使用 AppTest mock 与临时 SQLite。

### 限制

- 本轮只建立共享主题并接入 `Home.py`；`news.py` 的阅读页局部样式、简报页和图表内部配色未重新设计，后续轮按需对齐。
- 输入框/下拉框等复杂控件只补了可见焦点状态，未覆盖其内部背景与边框。Codex 已明确本轮不依赖 BaseWeb/React Aria 私有 DOM，留待后续轮用更稳妥的方式处理。
- 卡片统一样式通过 `aih-card-` key 接入；尚未给所有页面卡片加 key，未加 key 的 `border=True` 容器只共享边框色和圆角。
- 未在真实浏览器中截图核对；本轮视觉结论基于 CSS/AppTest 结构验证，最终观感以 Codex 审查为准。

## 第 2 轮：首页信息层次与历史状态（Codex 已审查）

Codex 独立审查：页面与旧、空、未来心跳等 4 项 mock AppTest 独立通过；既有断言保留，状态只表达记录新旧；Ruff 通过。最终视觉待统一部署。

### 问题

- 24h 指标为 0、图表为空时，下方仍显示历史新闻和历史心跳，容易被误读为正在运行。
- 指标、列表和心跳的时间口径没有就地说明；刷新按钮单独占一行。
- 心跳只显示时间，不区分旧记录、缺失和未来时间。

### 改动

- `dashboard/Home.py` 把日期说明与“刷新数据”按钮合并为一行（`[6, 1]` 列），按钮标签不变。
- 指标下新增口径说明：指标统计最近 24 小时；列表与心跳是库中最新记录，不代表近 24 小时发生或当前正在运行。
- `articles_24h == 0` 时显示简洁提示：可去「实时新闻」查看历史文章，或手动将图表范围切为最近 30 天；不自动改范围。
- “最新情报”下注明是库中最新文章、不限 24 小时。
- 新增 `heartbeat_status()` / `heartbeat_line()`：仅按 config 时区下的时间差判断，5 分钟内为“近期有心跳”，超出为“未观测到近期心跳”，缺失为“暂无记录”，未来时间为“记录时间在未来，无法判断”；没有“停止/健康”的硬编码结论。
- `tests/test_dashboard.py` 新增 1 个回归，覆盖旧调度心跳、未来 Worker 心跳（不得判正常）、缺值显示“暂无记录”，以及真实近期心跳才显示“近期有心跳”；同时校验无 24h 文章提示和列表口径。

### 实际验证

- 同一组 dashboard/reader mock 回归：`17 passed, 1 warning in 3.75s`（警告为依赖的 Starlette/httpx 弃用提示）。
- Ruff `check` 与 `format --check` 通过，`78 files already formatted`。
- 时区仍取 `/api/v1/settings` 的 config 值；图表默认范围仍是 7 天，未自动改写。

### 局限

- “近期”是 5 分钟显示阈值，不探测进程状态；Worker 长任务可能延迟心跳，因此不构成健康结论。
- 历史新闻和历史心跳仍会展示，只通过文案与状态避免误读，未隐藏历史数据。
- 未启动真实服务或浏览器截图；结论来自 mock AppTest 与静态检查，待 Codex 实看。

## 第 3 轮：地球仪可读性（Codex 已审查）

Codex 独立审查：独立运行可视化与简报相关 6 项 mock 测试通过，Ruff 通过。源码核对热度仅为相对数量，未知地区单列且未添加坐标，原视角和离线底图保留；浏览器视觉待统一部署。

### 问题

- 热区颜色没有色阶说明，无法判断“深/亮”表示什么，也容易被误读为风险等级。
- 无匹配地区或总量为 0 时，页面仍展示空地球，缺少“没有可定位依据”的明确说明。
- 地球依赖 WebGL 和悬停，缺少可折叠、可读文本的地区计数辅助。

### 改动

- `dashboard/visuals.py` 抽出统一 `HEAT_STOPS` / `HEAT_SCALE`，地球表面沿用同一色阶。
- 有地区依据时展示“相对热度 低→高”静态色阶，并注明按当前范围与当前依据内的最大值相对归一化，不是风险等级；图例带 `role="img"`/`aria-label`。
- 无地区依据时按总量和匹配量给出不同提示，明确“没有可定位的地区依据”、不生成热区、未知报道不标注在地图上；地图仍保留可旋转的空地球与离线轮廓。
- 新增 `region_count_rows()` 与可折叠“地区数量表（地图不可用/屏幕阅读辅助）”：仅列当前依据 > 0 的地区，按文章数降序、同数按名称排序，未知地区固定最后一行并注明不映射到地图；表格用 `st.table` 纯文本渲染并提供 `alt`。
- 保留可旋转地球、视角保持/重置、行业关注度图和地区报道选择；未改统计口径、来源国家语义或后端/配置。
- `tests/test_visual_reports.py` 新增 1 个行为测试：无依据时校验提示、无图例、表格只有未知行；有依据时校验图例/非风险说明及地区表排序和未知单列。

### 实际验证

- 同一组 dashboard/reader/visual mock 回归：`18 passed, 1 warning in 4.23s`（警告为依赖的 Starlette/httpx 弃用提示）。
- Ruff `check` 与 `format --check` 通过，`78 files already formatted`。
- 现有 globe 测试继续通过：空地区仍保留离线轮廓，orbit/`uirevision` 视角配置保持不变；新增行为测试覆盖空地区 UI。

### 局限

- 地区表只列当前依据大于 0 的地区，零计数地区不展开；未知行是文章数，不是地理坐标。
- 色阶描述的是当前范围内的相对数量，不构成风险、事件地点或事实核验结论。
- 未在禁用 WebGL 的真实浏览器中验证；辅助表作为可读替代，但浏览器截图待 Codex 实看。

## 第 4 轮：分类统计图可读性（Codex 已审查）

Codex 独立审查：独立运行可视化与页面 12 项 mock 测试通过，Ruff 通过；复核修正后的长名称坐标独立、HTML 转义和完整来源统计口径，既有断言保留。最终视觉待统一部署。

### 问题

- 趋势/行业/来源数量轴缺少统一单位，计数轴可能出现小数刻度。
- 行业/来源用短名称直接作为 Plotly 类别坐标时，前 15 字相同的长名称会被合并，条形与计数可能丢失。
- 语言图直接显示 `zh`/`en` 等代码；分类统计缺少可折叠的纯数据摘要。

### 改动

- `dashboard/visuals.py` 新增统一计数轴：标“文章数（篇）”、`tickformat="d"`，小范围用整数 `dtick`；趋势/行业/来源及热力图 colorbar 均避免小数刻度。
- 新增 `horizontal_count_figure()`：行业/来源共用唯一数字位置作 y 坐标，`tickvals`/`ticktext` 只负责短标签；完整名称放在 `customdata` 供 hover，因此短标签相同也保持独立条形和原计数。
- 短标签、`ticktext` 与 `customdata` 中的名称统一 `html.escape`，避免名称里的标签改变 Plotly 显示；行业/来源长名称可在 hover 和汇总表追溯完整值。
- 新增 `language_label()`：`zh`/`en` 等常见代码映射中文，`zh-CN` 按基础代码映射；未识别代码原样保留，空值显示“未知”。
- 新增可折叠“分类统计纯数据摘要”，包含行业、全部来源和语言的完整名称/代码及计数；注明多行业标签合计可能大于文章总量，重要性评分不在表内、不代表可信度。
- 来源图仍只取前 8 名，并新增范围说明。已核对 `app/services/analytics.py`：`source_counts` 对范围内每篇文章累计、返回全部来源；图表 `[:8]` 才是前 8 限制，摘要表使用完整列表（临时库实测两个来源均返回）。
- 原始配色、地球视角/重置、统计范围、行业图与地区报道选择均保留。

### 实际验证

- 同一组 dashboard/reader/visual mock 回归：`20 passed, 1 warning in 4.63s`（警告为依赖的 Starlette/httpx 弃用提示）。
- 新增行为测试覆盖两个前 15 字相同的长名称（计数 7/3）仍为不同位置、计数不变、完整名称可追溯且标签已转义；另覆盖语言代码映射与未知代码保留。
- Ruff `check` 与 `format --check` 通过，`78 files already formatted`。

### 局限

- 轴上仍使用带省略号的短标签，完整名称需看 hover 或摘要表；热力图用完整名称并依赖 `automargin`。
- 摘要表列出全部来源，来源较多时需展开后滚动；未在真实浏览器截图核对，最终观感待 Codex 实看。

## 第 5 轮：新闻筛选可理解性与重置（Codex 已审查）

Codex 独立审查：独立复核新闻筛选、搜索与阅读 8 项 mock 测试通过，Ruff 通过；重置仅触发 GET，页码归一，排序、紧凑、阅读偏好与收藏保留。保留全部既有回归断言，视觉待统一部署。

### 问题

- 筛选条件分散在搜索框和折叠区，用户看不到当前关键词、行业、来源、语言、时间与清单的组合。
- 没有统一清空动作；无结果时只有泛化提示，缺少直接恢复入口。
- 直接修改已创建控件的 `session_state` 容易触发 Streamlit 状态异常。

### 改动

- `dashboard/news.py` 为筛选控件增加显式 key；“清空筛选”按钮的 callback 只设置 pending 标记，下一次运行在创建任何控件前由 `apply_pending_clear()` 写回默认值，避免控件实例化后改状态。
- 新增当前筛选摘要：关键词、清单、行业、来源、语言、时间、分析状态。行业/来源显示名称、语言显示中文，不显示内部 ID。
- 清空搜索、行业、来源、语言、时间、分析状态和清单（回“全部”），回到第 1 页；保留排序、紧凑列表、阅读字号/宽度和收藏。排序与紧凑属于显示偏好，明确选择保留。
- 无结果提示改为“可检查关键词或时间范围，或直接清空筛选”，并提供使用同一回调的“清空筛选”按钮；不自动修改条件。
- 保留既有搜索/筛选、翻页、阅读器返回位置行为和主要按钮标签。
- 新增 `tests/test_news_filters.py` 一个 AppTest：输入关键词并叠加行业/来源/语言/时间/分析/清单筛选、到第 2 页后清空，验证第 1 页、27 篇结果、中文摘要、阅读偏好与收藏保留，且清空后的请求全是 GET。

### 实际验证

- 测试命令显式使用 memory 数据库与 AI/通知关闭；同一组页面回归共 `21 passed, 1 warning in 5.75s`（警告为依赖的 Starlette/httpx 弃用提示）。
- Ruff `check` 与 `format --check` 通过，`79 files already formatted`。
- 清空动作后无 POST/PATCH/DELETE；阅读字号 22/宽松与 1 篇收藏保持。

### 局限

- 筛选摘要是一行 caption，窄屏会换行；空结果处的“清空筛选”按钮与顶部共用回调，未单独做浏览器截图。
- 排序/紧凑偏好刻意保留，不等同于“恢复默认视图”；阅读清单则回到全部。
