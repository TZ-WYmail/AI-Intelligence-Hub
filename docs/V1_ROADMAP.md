# 初代产品分段验收目标

更新日期：2026-10-24。DeepSeek Harness 负责实现，Codex 负责范围、审查与验收。

## 执行边界

- 保留现有数据库、用户配置和凭据；项目生产服务维持停止状态。
- 真实通知不接入、不发送；凭据相关验证使用 mock，并明确与真实接口验证区分。
- 每段经过实际测试与独立审查后再提交，通过已配置的 GitHub SSH 远程同步。
- 不为追求测试通过而删减关键行为断言。失败和未验证内容如实记录。

## 第一段：失败任务恢复与运行日志

目标：用户可以筛选任务，安全重试采集、分析、日报和备份的失败任务，并理解操作结果。

验收条件：鉴权、状态校验、数据库条件更新、活动任务去重、失败审计保留、畸形参数拒绝、通知任务禁止重试；界面选择没有截断标识冲突，服务异常提示不泄露上游内容。全套测试与 Ruff 通过。

起点：保留的未提交改动，首次恢复运行得到 67 项通过、3 项失败。单独重跑其中 3 项得到 1 项通过、2 项失败，简报测试存在隔离或日期依赖，需查清。

状态：已验收并提交 `9d5701a`。完整套件 110 项、Codex 独立审查 13 项及 Ruff 检查通过。额外修复坏渠道参数阻断租约恢复、并发清理后访问过期 ORM 对象的问题。生产服务维持停止。

## 第二段：事件关联准确性

目标：不同金额、符号、币种、主体关系或结论的报道不会因标题相似被错误合并。

验收条件：保守关联策略；参数化反例及完整文章分析流程测试；同标题跨来源正例继续通过；保留历史数据，不自动提升验证状态。修复前已复现数字换位、正负号和币种误合并。

状态：已验收并提交 `93456c0`。35 项相关测试、6 项 Codex 独立反例及针对性 Ruff 检查通过。基准脚本增加事件数与未完成任务数的强制校验，待第三段实际运行。

## 第三段：部署与交付验收

目标：形成可复现的交付证据。

验收条件：前两段通过；全套自动化测试、mock 批量端到端基准、Compose 配置校验、镜像构建；更新部署、限制和验收文档；核查密钥未进入提交；SSH 同步远程并验证提交一致。不将镜像构建等同于生产运行或真实渠道验证。

状态：已验收。模拟基准通过（100 来源、3,000 篇文章、3,000 个事件、3,000 次模拟投递，失败与积压均为 0）。Compose 配置与镜像构建通过；无网络、只读临时容器完成内存数据库与 OpenAPI 加载检查。完整证据见 [V1_ACCEPTANCE.md](V1_ACCEPTANCE.md)。代码已通过 SSH 同步；本文件随最终文档提交同步。

## 下一段：真实来源复核与运行健康

目标：复核旧来源验证快照，区分目前可访问、过期、受限和无法确认的来源，查明 GDELT 的真实错误，并让来源健康信息便于理解。

验收条件：仅对公开来源做有超时和限流的受控验证；记录实际验证时间、解析结果与失败原因；不能确认的来源维持禁用，不编造地址或绕过限制。需要改动时仍由 DeepSeek 实现，经 Codex 审查和 mock 回归后提交。生产采集、项目真实 AI 与通知维持关闭；长期运行观察不冒充本轮已完成。

状态：前三段交付后继续推进；不将本轮自动化验收等同于完整 SRS 验收。

## 额度接续

已创建当前聊天的每小时自动接续任务。执行时先检查额度和目标状态；接近限制则保存进度，在限制窗口重置后继续。认证缺失时不绕过认证或重复派发。目标完成后停止自动接续。
